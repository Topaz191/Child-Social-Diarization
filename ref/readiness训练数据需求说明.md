# Readiness LSTM 训练数据需求说明（对外沟通稿）

> 用途：向数据持有方说明「规模化训练发言准备度（readiness）模型」需要哪些材料。  
> 本地现状：仅有南苑 `0820-post` 单视频可做链路验证；正式训练需补齐下列数据。

---

## 1. 训练目标

训练一个轻量时序分类器：输入某人在短时间窗口内的头部/嘴部特征序列，输出 **0–1 的发言准备度**（即将开口 vs 不会开口）。

| 样本类型 | 定义 | 标签 |
| :--- | :--- | :--- |
| 正样本 | 该说话人**真实开口前** 0.5–1.0 秒的视觉时序 | 1 |
| 负样本 | 同一视频中、**远离任何说话段**（建议 ≥2 秒）的静音/聆听窗口 | 0 |

因此：**需要同时有「视频画面」和「带说话人身份的时间标注」**，缺一不可。

---

## 2. 每场会话最低交付清单（必选）

请按「一场会话 = 一个可对齐的视频 + 一份时间轴标注」交付。

### 2.1 视频文件（必选）

| 项 | 要求 |
| :--- | :--- |
| 内容 | 小组讨论/干预会话画面，能看清学生面部 |
| 视角 | **优先双人/多人同框**（便于按座位对齐说话人）；单人镜头也可，但需能对应到标注中的 `S1/S2/...` |
| 分辨率 / 帧率 | 建议 ≥720p，≥15 fps（25 fps 更佳） |
| 时长 | 完整会话或与标注时间轴一致的剪辑版 |
| 音视频同步 | 画面与声音时间轴一致（误差建议 <100 ms） |
| 质量 | 干预目录中「视频质量=可用」优先；严重遮挡、长时间侧脸/出画需在备注中说明 |
| 命名 | 建议与现有规范一致，例如：`{试次}-G{组}-S{学生组合}-{前/后测}[-cut].mp4` |
| 格式 | MP4（H.264）或可被 OpenCV/ffmpeg 解码的常见格式 |

### 2.2 说话人时间标注（必选）

与现有南苑表 `202406-nanyuan-primary.xlsx` **同结构**即可，至少包含：

| 列名 | 含义 | 要求 |
| :--- | :--- | :--- |
| `trial` | 场次 ID | 与视频命名可对应（如 `0820`, `0908`） |
| `test` | `pre` / `post`（如有中测请统一编码） | 与视频阶段一致 |
| `sub` | 说话人：`S1`/`S2`/`S3`/`S4`/`T`… | **学生段必须可区分到个人** |
| `start_abs` | 段起始时间（秒，或 `HH:MM:SS`） | 同一会话内可用统一时间原点 |
| `end_abs` | 段结束时间 | 必须 `end > start`（请先清洗负时长/错段） |
| `content` | 转写文本 | 可选，但有助于质检 |

**说明：**

- 我们只用学生段（`S1–S4`）做正样本；教师 `T` 可保留但训练时可忽略。
- 时间轴需与视频对齐：若标注相对「整场原始录像」、视频是剪辑版，请同时提供 **剪辑偏移量**（秒）或直接提供与视频对齐后的标注。
- `apt` / `reg` 干预编码**不是**本模型训练所必需，有则更好（后续分析用）。

### 2.3 画面位置 ↔ 说话人对应（强烈建议）

多人同框时，需要知道「画面左边是谁」。任选一种交付：

| 方式 | 内容 |
| :--- | :--- |
| A. JSON 映射（推荐） | 如现有 `*_position_gt_verify.json` 中的 `gt_speaker_to_position`：`S1→右中` 等 |
| B. 文字说明 | 「从左到右：S2, S3, S1」+ 一张截图 |
| C. 单人镜头 | 文件名或目录标明说话人（如 `...-S3.mp4`），可省略位置映射 |

没有映射时我们只能自动估计，会引入标签噪声，影响 readiness 训练质量。

## 4. 可选但有帮助的材料

| 材料 | 用途 |
| :--- | :--- |
| 纯净声纹注册 WAV（每人 3–10 秒） | 非 readiness 必需；用于后续 CSD 融合对比 |
| 干预目录行（场地/音视频质量/备注） | 过滤「不可用」场次 |
| 已知问题列表（遮挡、串麦、学生离座） | 排除脏样本 |

---

## 5. 我们不需要对方提供的内容

- 不需要对方预先抽取 yaw/pitch/嘴部开合特征（我们有脚本从视频抽取）。  
- 不需要对方标注「准备度」分数（由说话段起止自动生成正负样本）。  
- 不需要 GPU 环境；对方只需提供原始视频 + 时间标注（+ 位置映射更佳）。

---

## 6. 交付验收标准（对方自检可用）

一场数据可进入训练流水线，当且仅当：

1. 视频能正常解码，时长与标注覆盖区间基本一致；  
2. 标注中至少有 **≥30** 条有效学生说话段（`end > start`，时长 ≥0.4 s）；  
3. 学生身份 `S1/S2/...` 与画面可对应（有位置映射或单人镜头）；  
4. 段间存在若干 **≥2 s** 的静音间隔（用于负样本；若几乎无静音，需说明，我们改用段内聆听者策略）。

粗算：每场约可得到数十到数百条平衡正负样本；18 场合计有望达到**数千级**样本，满足远程 GPU 训练。

## 7. 一句话需求（可直接转发）

> 请提供南苑小学已有说话人时间标注的各场次**原始/剪辑视频**（优先双人同框、音视频可用），文件命名或清单能对应到 `trial + pre/post`；若多人同框，请附带「画面位置→S1/S2/S3」说明。标注已有 Excel 即可，但需确认与视频时间轴对齐。我们自行抽视觉特征并生成「开口前 / 静音」训练样本。

## 8. 本地原型已跑通（供内部对齐）

| 脚本 | 作用 |

| 项 | 结果 |
| :--- | :--- |
| GT 学生段 | 98 |
